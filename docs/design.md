# rnd-program-logic 설계서 (2026-10-20)

## 한 문장

사업의 투입–활동–산출–결과 사슬과 성과지표·목표치를 YAML 설계서로 받아, 끊긴 고리·지표 적합성·목표치 근거 유무를 **지침 항목에 묶인 규칙**으로 기계 점검하고, 점검표·지표표·논리모형 SVG·「지어내지 않은 것」 절을 내는 명령줄 도구.

## 어디서 왔나

- 나노조합 「첨단나노 상용화 기술개발 사업 논리정립」 연구(2026-09)에서 손으로 한 일: 내역별 투입→활동→산출→성과→영향 표(<표 7-13>), 사업 목표별 산출·성과 지표 후보표(<표 7-14>), 선행 특정평가(나노융합2020)가 매출 지표에 단 유보를 지표 설계 원칙으로 승계. 표를 손으로 그리면 "O3이 어느 결과로도 안 간다"는 것을 사람이 눈으로 찾아야 했다.
- rnd-eval-skills `program-logic-check`(문서를 읽고 다섯 칸에 옮겨 끊김 유형 5가지를 짚는 스킬)의 점검 축을 그대로 잇되, 이 도구는 **설계서를 기계 점검**한다. 스킬은 읽고 판정하는 일, 도구는 설계 단계에서 빈 칸·끊김·근거 없는 목표치를 구조로 드러내는 일.
- 점검 질문은 `indicator-audit`의 Q1~Q7(연계성·유형·단계·질적·산식·외부요인·목표치)을 규칙으로 옮긴 것.

## 흐름

```
init ──▶ program.yaml ──▶ check ──▶ check.json(판정·근거·확인 필요)
                            │
                            ├──▶ render ──▶ logic_model.svg/.html + figure_spec.json(doc-figure structure-block)
                            └──▶ report ──▶ report.md (0 기본 칸 · 1 사슬 표 · 2 연결 판정 · 3 점검표 · 4 지표표 · 5 지어내지 않은 것 · 6 그림 · 7 근거 표 · 8 정직성 규칙)
```

policy-did 와 달리 FAIL 이 다음 단계를 막지 않는다. 추정치가 없으므로 "틀린 숫자가 나가는" 위험이 없고, 끊김을 **그림으로 보여 주는 것**이 목적이기 때문이다. 종료 코드만 3으로 돌려 CI 에서 걸 수 있게 했다.

## 설계 결정

| 결정 | 이유 |
|---|---|
| 노드마다 `because`(그래서 문장) 칸 | 스킬의 핵심이 "칸 사이의 '그래서'가 문서에 적혀 있는가"였다. 연결선은 있으나 문장이 없으면 점선으로 그리고 WARN — 연결은 설계자의 가정이라는 뜻 |
| 끊김 ≠ 판정 | '끊김'은 설계서에 연결이 없다는 사실. 사업에 논리가 없다는 평가가 아니다. 보고서 정직성 규칙 2 |
| 근거 대장 `EVIDENCE` 에 `status` 필드 | 점검 항목마다 지침·조문을 적되, 원문을 못 읽은 것은 `확인 필요`로 찍는다. 자율평가 지침·재정사업 성과관리 기본계획·특정평가 일반 지침이 그렇다. 테스트가 "확인이면 날짜, 아니면 None"을 강제 |
| 안내서 장 번호는 **추출본 기준 Ⅴ** | 읽은 6차 안내서 추출본의 목차에서 성과지표는 Ⅴ장(설정 주안점 Ⅴ.3 p.33 · 측정방법 Ⅴ.4 p.39 · 목표치 Ⅴ.5 p.42 · 수정 Ⅴ.6 p.43), 논리모형은 Ⅲ.1 사업 분석(p.8~10). rnd-eval-skills 는 같은 절을 Ⅳ로 적고 있어 어느 한쪽이 판 차이거나 오기다 — 이 도구는 읽은 판을 따르고 쪽수를 함께 적는다 |
| 대체 지표·목표치 숫자 제안 금지 | indicator-audit 의 규칙 계승. 수정 제안은 "무엇이 빠졌는가"까지 |
| 투입·과정 지표 = 부적정, 산식의 과정 항목 = 부적정 | 안내서 Ⅴ.3④·Ⅴ.4②가 "적절한 성과지표로 볼 수 없음"으로 단정한 두 가지만 FAIL. 나머지(질적 과반·목표별 2개·외부요인)는 '권장·지양' 표현이라 WARN |
| 기계적 점증 탐지 = 등차·등비(±1%) 3점 이상 + 근거 문장의 "전년·추세 … 상향·적용" 패턴 | 안내서 Ⅴ.5①의 "기계적으로 점증형 목표치". 나노융합2020 <표 3-10>의 근거 문장이 전부 이 패턴이고 평가원도 과거 실적치 타당성을 지적했다 |
| 매출·수출·생산액 지표는 기여율·순효과 글자가 있어야 통과 | 안내서 Ⅴ.4③ + 특정평가 권고. 단 글자가 있다고 충분하지 않다(평가원은 기여율 산식이 있는데도 직접 수혜 반영을 요구) — 한계로 명시 |
| SVG 직접 생성 + doc-figure 스펙 병행 | 표준 라이브러리만으로 끊김을 빨간 점선으로 그린다. 같은 내용을 프리셋으로 다시 그리고 싶으면 `figure_spec.json` 을 doc-figure `render_figure.py --html-only` 에 넣는다 |
| 작은 YAML 파서, 정수 키는 int | 의존성 0. PyYAML 과 같은 결과를 내는지 예시 2건으로 테스트(연도 키 `2027:` 가 처음에 문자열로 읽혀 어긋났던 것을 고침) |

## 점검 항목

사슬 C1~C12(목표 존재 · 다섯 칸 · 참조 무결 · 산출 없는 활동 · 결과 없는 산출 · 전략목표 미연결 · 고아 · 그래서 문장 · 투입의 결과 둔갑 · 내역사업 분기 · 사업유형/수명 주기 · 주변 여건) / 지표 I1~I10(재는 노드·단계 일치 · 투입과정 · 목표별 2개 · 질적 과반 · 단순 건수 · 결과 지표 유무 · 산식/과정 항목/이름–산식 어긋남 · 외부요인·직접 수혜 · 복합지표 · 비기초 논문) / 목표치 T1~T6(연차 목표치 · 설정 근거 · baseline · 기계적 점증 · 실적 저조로 하향 · 근거 출처). `python3 program_logic.py evidence` 가 항목별 근거와 확인 상태를 찍는다.

## 예시 2건에서 확인한 것

- **합성**(결함 11개를 심음): 산출 없는 활동·결과 없는 산출·미연결 목표·because 없음·결과 칸의 '참여기관 수'·투입지표·위원회 운영 건수 산식·기여율 없는 매출·등차 목표치 3건·'전년 실적 10% 상향' 근거·baseline/근거/목표치 없는 지표 — 전부 잡힘, 깨끗한 노드에는 오탐 없음(tests).
- **나노융합2020**(KISTEP 특정평가 보고서 원문만으로 사후 재구성): 끊김 4(기술교류회 활동의 산출 없음, 등록특허·상용화 지원 건이 결과로 안 이어짐, '사업화 성공기업 15개' 목표에 닿는 결과 노드 없음)·보완 14·확인 필요 5. 목표치 근거가 전부 '전년 실적·추세 n% 상향'이라는 점이 평가원의 지적과 같은 자리에서 걸렸다. 평가원이 지적한 매출의 1개 기업 집중은 설계서 점검으로는 나오지 않는다(실적 자료의 몫).

## 하지 않는 것

- 지표의 뜻이 맞는지(이름–산식 일치의 의미 판단), 사업유형별 기대 성과 분야의 적합성 판정 — 글자 규칙으로는 못 한다. 몇 가지 어긋남 쌍(활용도↔만족도 등)만 안내서 사례에서 가져왔다
- 실적 대비 달성도, 효과 추정(policy-did), 출처 실재 확인(fact-verify)
- 영향(impact) 칸 — 안내서가 "사업평가보다 효과성 분석의 대상"으로 둔 것을 따라 그림에서 뺐다. 필요하면 `outcomes_long` 에 적는다
