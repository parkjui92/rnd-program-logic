# rnd-program-logic — 사업 논리모형·성과지표 설계 점검기

정부 R&D 사업의 **투입 → 활동 → 산출 → 결과(단기) → 결과(장기)·성과목표** 사슬과 성과지표·목표치를 설계서(YAML)에 적으면, 끊긴 고리·지표 적합성·목표치 근거 유무를 점검해 **점검표 + 지표표 + 논리모형 그림(SVG) + 「지어내지 않은 것」 절**을 냅니다. 점검 항목마다 어느 법 조문·어느 지침 어느 절을 따르는지 적혀 있고, 원문을 확인하지 못한 근거는 **[확인 필요]**로 찍힙니다.

표준 라이브러리만 씁니다. 설치 없음, API 키 없음, 브라우저 없음.

```bash
python3 program_logic.py init --out program.yaml        # 설계서 서식
python3 program_logic.py check program.yaml --out out   # 점검 → out/check.json (끊김·부적정이면 종료 코드 3)
python3 program_logic.py render program.yaml --out out  # 논리모형 그림 → out/logic_model.svg/.html + figure_spec.json
python3 program_logic.py report program.yaml --out out  # 전부 → out/report.md
python3 program_logic.py evidence                       # 점검 항목 → 근거 지침과 확인 상태
python3 program_logic.py selftest
```

## 왜 설계서인가

사업 논리는 보통 설명자료 여기저기에 문장으로 흩어져 있고, 평가 때 "활동만 있고 산출이 없다", "산출이 누구에게 무엇을 바꾸는지 없다", "목표치 근거가 전년 실적 10% 상향뿐이다"가 지적됩니다. 이 도구는 그 다섯 칸을 **먼저 설계서에 쓰게 하고**, 칸 사이의 연결(`uses`·`from`·`goal`)과 연결의 '그래서' 문장(`because`), 지표가 재는 노드(`measures`), 목표치의 근거(`target_basis`)를 칸으로 둡니다. 비어 있으면 비어 있다고 나옵니다. 문서에 없는 것을 메우지 않습니다.

[rnd-eval-skills](https://github.com/parkjui92/rnd-eval-skills)의 `program-logic-check`(문서를 읽고 판정하는 스킬)의 상위 도구입니다. 스킬의 끊김 유형 다섯 가지(산출 없는 활동 · 결과 없는 산출 · 전략목표 미연결 · 투입이 결과로 둔갑 · 내역사업 분기)와 `indicator-audit`의 지표 질문 Q1~Q7을 규칙으로 옮겼습니다. 나노조합 사업 논리정립 연구에서 손으로 그리던 논리모형 표·지표 후보표를 도구로 굳힌 것입니다.

## 설계서

`init`이 쓰는 서식의 핵심:

| 절 | 내용 |
|---|---|
| 기본 칸 | 소관·기간(기한/계속)·총사업비·**사업유형**(안내서 Ⅲ.2 10유형, 추정이면 `program_type_basis`에 `[추정]`)·수명 주기 |
| `strategic_goal`·`performance_goals` | 전략목표와 성과목표(id·원문·출처) |
| `chain` | `inputs` → `activities(uses)` → `outputs(from)` → `outcomes_short(from, because)` → `outcomes_long(from, goal, because)`. 노드마다 원문·출처 |
| `indicators` | 지표명·`stage`(투입/과정/산출/결과)·`measures`(재는 노드)·`goal`·`kind`(질적/양적)·산식·연차별 `targets`·`baseline`·`target_basis`·`target_source`·`external_factors`·목표치 하향 이력 |
| `context` | 주변 여건(외부 환경)·겹치는 사업 |
| `sub_programs` | 내역사업. 둘 이상이면 활동·지표·목표에 `sub_program` 표시 |

## 점검 항목과 근거

| 묶음 | 항목 | 근거(원문 확인) |
|---|---|---|
| 사슬 C1~C12 | 전략·성과목표 존재 / 다섯 칸 / 참조 무결 / **산출 없는 활동** / **결과 없는 산출** / **전략목표 미연결** / 고아 노드 / '그래서' 문장 / **투입이 결과로 둔갑** / **내역사업 분기** / 사업유형·수명 주기 / 주변 여건 | 「국가연구개발사업 등의 성과평가 및 성과관리에 관한 법률」 제6조①② · 「국가재정법」 제85조의2①1 · 과기정통부 「성과목표·지표 설정 안내서」(6차) Ⅲ.1 사업 분석(논리모형)·Ⅲ.2 사업유형 · 제5차 성과평가 기본계획(2025-10-30 심의) |
| 지표 I1~I10 | 재는 노드·단계 일치 / 투입·과정 지표(**부적정**) / 목표별 2개 / 질적 과반 / 단순 건수 / 결과 지표 유무 / 산식 유무·과정 항목(**부적정**)·이름–산식 어긋남 / 매출·수출의 기여율·순효과 / 복합지표 / 비기초 논문 | 안내서 Ⅴ.3 ①~④ · Ⅴ.4 ①~④ · 부록3 · 같은 법 제3조⑤·제12조④ · KISTEP 나노융합2020 특정평가(2019) 권고 |
| 목표치 T1~T6 | 연차 목표치 / 설정 근거 / baseline / **기계적 점증**(등차·등비, '전년 실적 n% 상향') / 실적 저조로 하향(**부적정**) / 근거 출처 | 안내서 Ⅴ.5 ①~③ · Ⅴ.6 |

판정 등급은 `오류`(설계서가 읽히지 않음) · `끊김`(사슬에 연결이 없음) · `부적정`(안내서가 "성과지표로 볼 수 없음"으로 단정한 것) · `보완`(지양·권장) · `확인 필요`(입력에 없음) · `적정`. 전체 판정은 끊김·부적정이 하나라도 있으면 FAIL.

**원문을 확인하지 못해 [확인 필요]로 둔 근거**: 기획재정부 「재정사업 자율평가 지침」 평가항목(2026년부터 부처 자체평가 폐지·통합 재정사업 성과평가로 개편, 보도 기준) · 「재정사업 성과관리 기본계획(2022~2026)」 · 특정평가 일반 지침(「(가칭)국가연구개발 특정평가 세부 운영규정」은 제5차 기본계획에 '마련' 예정으로만 적힘). 이것들은 어떤 점검 항목의 1차 근거로도 쓰지 않았습니다. 확보되면 `EVIDENCE`에 절·쪽을 적고 상태를 올립니다.

안내서의 장 번호는 읽은 6차 추출본의 목차를 따릅니다(성과지표 = Ⅴ장, 논리모형 = Ⅲ.1). rnd-eval-skills는 같은 절을 Ⅳ로 적고 있어 어느 쪽이 판 차이인지 확인이 필요합니다 — 쪽수를 함께 적어 두었습니다.

## 출력

- `report.md` — 0 기본 칸 · 1 사슬 표(원문·상류·출처) · 2 연결 판정 · **3 점검표(항목·판정·위치·내용·근거 지침·수정 제안)** · **4 지표표(지표–성과목표–재는 노드–단계–질적/양적–산식–목표치–baseline–근거–외부요인–판정)** · **5 지어내지 않은 것** · 6 그림 · 7 근거 표(확인 상태·확인 방법) · 8 정직성 규칙
- `logic_model.svg` / `.html` — 다섯 열 논리모형. 끊긴 노드는 빨간 점선, '그래서' 문장이 없는 연결은 점선, 지표는 재는 노드 아래 칩(K…), 아래에 성과목표·전략목표 띠와 [확인 필요] 건수
- `figure_spec.json` — [doc-figure](https://github.com/parkjui92/doc-figure) `structure-block` 스펙. 프리셋으로 다시 그리려면 `render_figure.py figure_spec.json --html-only`
- `check.json` — 판정·항목별 근거·확인 필요 목록·설계서 sha

## 예시

- `examples/synthetic/` — 결함 11개를 일부러 심은 합성 사업(실존 사업 아님). 전부 잡히고 깨끗한 노드에는 오탐이 없는지가 테스트.
- `examples/nano2020/` — **실제 공개 사업**: 나노융합2020사업(과기정통부·산업부, 2012~2020)을 KISTEP 특정평가 보고서(2019-10) 원문만으로 사후 재구성(`sources.md`에 쪽). 끊김 4·보완 14·확인 필요 5. <표 3-10>의 목표치 근거가 전부 "전년 실적·추세 n% 상향"이라 T4가 지표 5개에서 걸리는데, 평가원도 같은 자리("과거 실적치의 타당성 미흡")를 지적했습니다. 평가원이 지적한 매출의 1개 기업 62% 집중은 설계서 점검으로는 나오지 않습니다.

## 정직성 규칙 (출력에 그대로 찍힙니다)

1. **입력에 없는 것을 메우지 않는다.** 산출·결과·목표치·법령 조항이 설계서에 없으면 [확인 필요]로 남는다. 빈 칸은 빈 칸으로 그린다.
2. **'끊김'은 사실이지 평가가 아니다.** 설계서에 연결이 적혀 있지 않다는 뜻이며, 문서에 있는데 옮기지 않았을 수 있다.
3. **근거는 항목마다, 확인 상태와 함께.** 원문을 읽지 못한 지침은 '확인 필요'로 표시하고 1차 근거로 쓰지 않는다.
4. **대체 지표·목표치 숫자를 제안하지 않는다.** 수정 제안은 "무엇이 빠졌는가"까지다.
5. **기계가 보는 것은 글자다.** 기여율이라는 말이 산식에 있으면 통과시키지만, 그것이 직접 수혜를 제대로 반영했는지는 사람이 본다(나노융합2020에서 평가원은 기여율 산식이 있는데도 직접 수혜 반영을 요구했다).
6. **설계서 sha를 출력에 적는다.** 설계서가 바뀌면 다시 돌린다.

## 검증 상태 (2026-10-20)

- tests 20건 통과(`python3 program_logic.py selftest`) — 소형 YAML 파서와 PyYAML의 일치(예시 2건), 합성 결함 11개 적발·오탐 0, 깨끗한 설계서는 끊김·부적정 0, 참조 오류·빈 칸·목표치 하향·이름–산식 어긋남 경로, 근거 대장 무결(확인이면 날짜·아니면 None), 보고서 8절·SVG 표기·doc-figure 스펙 5층
- 예시 2건 전 경로 산출(`examples/*/out/`), SVG는 브라우저에서 육안 확인
- 법 조문 4건은 국가법령정보 현행 원문, 안내서·기본계획·특정평가 보고서는 원문 추출본으로 대조

## 한계

- 글자 규칙이다. 지표 이름과 산식이 **뜻으로** 같은 것을 재는지, 사업유형별 기대 성과 분야에 맞는지는 판정하지 않는다(안내서가 든 어긋남 사례 몇 쌍만 본다)
- 실적·달성도·효과 추정은 범위 밖([policy-did](https://github.com/parkjui92/policy-did)), 출처 실재 확인도 범위 밖([fact-verify](https://github.com/parkjui92/fact-verify))
- '영향(impact)' 칸은 그리지 않는다(안내서: 사업평가보다 효과성 분석의 대상). 필요하면 장기 결과에 적는다
- 소형 YAML 파서는 서식의 부분집합만 읽는다(앵커·다중행 블록 없음). PyYAML이 있으면 그것을 쓴다
